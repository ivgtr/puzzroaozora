# 青空パズル仕様 — 原稿の修復

2026-09-27 / 問題・保存形式 v2。Issue #1と子Issue #2〜#4に対応する現在の仕様。旧スコア・先頭固定・回答送信中心の計画を置き換える。

## 体験と進行

作品選択 → 原稿を読む → 伏せて紙片を広げる → 好きな箇所から組み立てる → 同じ原稿用紙へ戻る。時間制限、ライフ、正解送信ボタン、スコア、ランキングは設けない。

Easyは元の紙片2枚、Normalは3枚、Hardは4枚で新しい塊を確定する。見た目のオブジェクト数ではなく元の紙片数を数える。確定した塊へは前後いずれも1枚から追加でき、確定した塊同士も接続できる。端数が残っても完成できる。

新規候補は先頭以外でもよい。照合は原文に対する文字列で行い、同一テキストの紙片は交換できる。反復語句の出現位置を最初に固定しない。候補を確定した結果、他の確定済みブロックと残りの紙片を使って全文を再構成できることを確認する。

不一致でも仮組みを残す。仮の境界だけを外せる。確定した部分を含む仮組みでも確定済みの内側は壊さない。Undoは直前64操作の状態と座標を保持し、移動・接続・分離・完成を戻せる。座標だけの移動も一操作であり、ドラッグの各フレームは履歴に入れない。

## 状態と責務

`Session`は`reading / assembling / complete`と、紙片ID・並び・確定境界・ワールド座標だけを持つ。紙片IDはランダムで、正解位置を含まない。塊IDは先頭の紙片IDとし、前付け後の分離でも重複しない。

PhaserのSceneがセッションを所有する。ドラッグ中の仮座標、選択、カメラ、音、Tweenは表示側の状態。接続は明示的なドロップまたは選択後の端タップでのみ評価する。近傍通過・ホバーで正誤判定しない。接続候補の見た目は正誤によらない。

Reactは読み取り専用スナップショットをアクセシビリティへ投影する。組立中に原文を隠したあと、読み上げ用DOMにも原文を残さない。原文見直しを開いた時だけ意図的に公開する。

## 原稿と難易度

推奨原稿は『吾輩は猫である』『檸檬』『銀河鉄道の夜』の異なる10抜粋。`src/data/passages.ts`に原文、出典、抜粋位置、手作業の分割、気付きの狙いを記録する。同じ短い原稿で確定枚数だけを比較できる導線も用意する。

自動取り込みの初期条件はEasy 100〜160字/10〜14枚、Normal 160〜240字/16〜22枚、Hard 220〜320字/22〜30枚。推奨原稿の文章量は編集した抜粋を優先し、機械的な文字数合わせのために文を継ぎ足さない。実際の文字数・枚数は検証記録に残し、人間の難易度確認と区別する。

表示上の原文と比較文字列を分ける。比較ではCRLFを改行に統一し、段落頭の字下げと改行を除く。NFKC、現代仮名への変換、句読点削除、一般空白の一括削除は行わない。400字に合わせた水増しは禁止。

## 完了の確認

ルールの少数の自動テストと本番ビルドに加え、実ブラウザで読み始めから完成までを確認する。読みやすさ、音の聴感、局所解を発見する面白さは自動的に合格とはしない。検証済み・未実施を`docs/verification.md`とPRに分けて記録する。
